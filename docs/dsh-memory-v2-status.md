## 已知问题（诚实的清单）

1. **scope 身份对不上**（已修，待生效）
   `pre-step` 绑定的对象 ≠ `systemPrompt.context` 收到的 `context.scope`。修复后多会话时不再借错，但退化为「不给查询」，注入质量下降。`scope_probe` 生效后才能决定是否改成确定性匹配。

2. **工具 schema 曾静默失效**（已修）
   `type: ['object','null']` 不合法 → `tools.register` 抛异常 → 因为共用 try 块，工具/提示词上下文/观察器全部没注册，而路由正常，插件看起来是好的。现在每次注册独立 try 并打日志。

3. **提炼规则只用关键词**
   召回靠「记住 / 决定 / 我更喜欢 / 以后都」这类显式说法，隐式偏好（"这样太长了"）抓不到。精度优先是有意的选择。

4. **注入不看会话归属**
   记忆都是 `global` scope，没有 workspace 级隔离。多项目使用时可能串味。

5. **没有向量检索**
   加入了一张小型中英同义词表补召回缺口（shell↔命令行 等）。评估集目前 10 条全部命中，但语料只有 10 条。

## 用户需要做的两件事

1. **刷新记忆页** → 应看到「记忆库内容（N 条）」，可确认账本里现在有什么
2. **重启 DSH** → 激活 scope 修复 + 候选自动进队列

重启后建议先说一句带「记住」的话，例如「记住我偏好简洁的中文回答」，下一轮即可检查候选是否落库。
